# Source mapping

Reference revision: `19905b75dbea89fbfd424d67fe26c81aaed0e018`. Paths are in the frozen McInPoker tree, repository `george-mcintyre/mcinpoker`; the recipe has no release files. The standard's platform list has no entry for release tooling, so the files sit under `implementation/server/` and install under `components/ourapps-release/server/`.

Scripts (Python, standard library only), `implementation/server/scripts/`:

- `scripts/release-targets.py` lines 1-111 -> `release_targets.py`: `read`, `check`, `require`, `merge`, `packages`, `publishes` kept as they are, including refusing redirects, requiring six booleans and exit code 3 for nothing switched on. Generalised: the user agent, the default store address (now `STORE_API`, default `https://ourapps.app`) and a new `PIPELINE_TARGETS` environment variable that switches off targets the pipeline does not build; file reads close their files. The store contract (`/api/build/<id>/targets`, six targets, `pwa` for web) is taken verbatim.
- `scripts/platform-manifest.py` lines 1-82 -> `platform_manifest.py`: verbatim apart from a usage header and `IndexError` on missing arguments.
- `scripts/publish-release.sh` lines 80-97 (the inline `jq` that builds `my-app.json`) -> `app_manifest.py` `build`: the poker name, description, player counts, bundle identifier and Apple minimum versions become `release/app.json` fields and `extra`; entries exist only for configured targets. `validate` is new (`generated-platform`: the checks follow `.opencode/knowledge/app-manifest.md`, the store's contract) and runs on the final merged manifest before upload.
- `scripts/publish-release.sh` lines 1-131 (the rest) -> `publish_release.py`: the same steps in the same order (changelog section, switches read before any write, optional verified packages, draft release, assets, manifest last, switches read again, previous manifest merge, publish as latest), rewritten in Python so it can be tested with a stand-in `gh` and without `jq`. Differences: `gh api` answers are parsed as JSON instead of `--jq`; the APK and `web.zip` asset names are `app.apk` and `web.zip` (the APK was `mcinpoker.apk`); release name and tag use the application name; the screenshot folder, iPad folder and changelog are arguments; arguments are validated.
- `scripts/platform-artifacts.py` lines 1-190 -> `platform_artifacts.py`: `inspect-apple`, `check-export`, `installer-certificate`, `record-package` and `record-windows` generalised: the bundle identifier, application bundle name, Mac category, Windows file prefix and executable name are arguments instead of `com.georgemcintyre.mcinpoker`, `McInPoker.app`, `card-games` and `mcinpoker-`. `prepare-project` (lines 30-57, which rewrites an XcodeGen spec for an isolated build of the McInPoker tree) is left behind.

Templates, `implementation/server/templates/` and `implementation/server/render.ts` (new; `@@name@@` tokens and `@@if flag@@` blocks, because GitHub's `${{ }}` cannot appear in aepm templates):

- `.github/workflows/release.yml` lines 1-307 -> `workflows/release.yml.template`: jobs version, android, web, ios, testflight, publish and their switch-read order are kept. Generalised: jobs exist per enabled target; secret names come from references; store address from `manifestUrl`; signing variable prefix; artefact names from the application id; the publish step calls `publish_release.py` with `--app release/app.json`; the Gradle wrapper is created when missing (android-host does not ship it). Left behind: the download of `install-banner.js` from the store (lines 137, 139; web-host ships the banner as source), the poker icon and screenshot paths (now options).
- `.github/workflows/ci-web.yml`, `ci-android.yml`, `ci-server.yml` (lines 1-35 each) -> `workflows/ci-*.yml.template`: directories and versions become options; `ci-server` drops `wrangler types`.
- `.github/workflows/platform-packages.yml` lines 1-93 -> `workflows/platform-packages.yml.template` and `.github/workflows/apple-testflight.yml` lines 1-82 -> `workflows/apple-testflight.yml.template`: jobs included per enabled desktop and Apple target; target requirement first, as before. `apple-upload-existing.yml` and `apple-upload-status.yml` are left behind.
- `scripts/build-windows.sh` lines 1-24 -> `scripts/build-windows.sh.template`; `scripts/inspect-windows.ps1` lines 1-29 -> `scripts/inspect-windows.ps1.template`; `scripts/build-apple-testflight.sh` lines 1-81 -> `scripts/build-apple-testflight.sh.template`: application names, directories, store address and the environment variable prefix (was `MCINPOKER_`) become tokens; `check-export` now receives the bundle identifier. The Apple script still calls `apple-testflight.py`, `apple-testflight-upload.py` and `ios/build-platform.sh`, which are left behind (see INSTRUCTIONS.md).

Left behind from `scripts/`: `apple-testflight.py`, `apple-testflight-upload.py`, `reserve-apple-build.py`, `continue-apple-upload.py`, `read-apple-upload-status.py`, `apple-existing-upload.json`, `check-platform-origin.mjs`, `layout.py`, `screenshots.py`, `sounds.py` and their tests (`test-apple-*.py`, `test-reserve-apple-build.py`). The tests `test-release-targets.py` (352 lines) and `test-platform-distribution.py` are the model for `tests/test_release.py`, which is rewritten for the generalised scripts. `ios/build-ipa.sh` and `ios/build-platform.sh` are not extracted.

`storeCredentials` is optional (no recipe or McInPoker lines). `render.ts` sets the flags `store` or `nostore`, drops `ios` from the release flags and from `PIPELINE_TARGETS` when there are no credentials, and skips `apple-testflight.yml` and `build-apple-testflight.sh`; the templates wrap every store secret, `STORE_API`, the `store-release` trigger and the TestFlight link in `@@if store@@` and add `STORE_MODE: "none"` under `@@if nostore@@`; `release_targets.py` `read` returns the `PIPELINE_TARGETS` as switched on when `STORE_MODE=none` (`generated-platform`: tests added in `tests/test_release.py` and `tests/release.test.ts`).
